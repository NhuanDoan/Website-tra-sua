# Debugging Skill

## Goal

Find the root cause before changing code.

## Workflow

1. Understand expected behavior.
2. Understand actual behavior.
3. Identify the affected feature.
4. Reproduce the problem.
5. Read the error/log.
6. Trace the execution flow.
7. Identify the root cause.
8. Identify side effects.
9. Propose the smallest safe fix.
10. Define a regression test.
11. Implement only after approval.
12. Validate.

## Rules

- Do not immediately rewrite code.
- Do not guess when evidence is available.
- Do not change unrelated code.
- Fix the root cause rather than symptoms.
- Preserve existing architecture.
- Explain why the bug occurs.
- Consider edge cases.
