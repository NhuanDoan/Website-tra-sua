# Project Analysis Skill

## Goal

Understand an existing project before modifying, migrating, or refactoring it.

## Workflow

1. Inspect the project structure.
2. Identify pages and entry points.
3. Identify reusable UI.
4. Identify application behavior.
5. Identify data sources.
6. Identify styling architecture.
7. Identify JavaScript behavior and dependencies.
8. Identify assets.
9. Identify important business rules.
10. Identify risks and technical debt.
11. Separate facts from assumptions.
12. Recommend the next smallest actionable step.

## Rules

- Do not modify files.
- Do not invent missing requirements.
- Do not assume behavior that is not supported by the code.
- Do not propose unnecessary dependencies.
- Do not recommend a rewrite without evidence.
- Preserve existing functionality during migration.
- Prefer incremental migration.

## Output

Return:

### Current Architecture

### Pages / Features

### Reusable Components

### Data / State

### Existing Behavior

### Dependencies

### Risks

### Technical Debt

### Recommended Next Step

Keep the analysis concise and evidence-based.
